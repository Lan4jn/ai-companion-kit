# 群桥历史可信 scope：现状和实现约束

本文件仅记录隔离副本中的代码审计；不是已完成的功能或部署方案。

## 现状

* `OneBot` 的入站认证仅当构造传入 `ingressAuthentication` 时可用：显式信任 127.0.0.1 明文 WS，或 TLS CA 加证书指纹。连接被认证不等于 QQ 平台提供端到端签名；本机模式也无法认证本机进程。`index.js` 当前仅在启用 durable chat 时通过 `createMainDurableTransport` 配置这一认证。
* 已有 `snapshotAuthenticatedOneBotPrivateMessage` 将已认证连接上的主人私聊事件与真实对象绑定；群事件没有对应的经认证快照。其事件字段要防修改，不能用任意传入的对象或模型参数替代。
* `Brain` 的 `read_group_chat` 目前经 `executePhoneTool` 直接调用 `readGroupChat`；`group-bridge.js` 的白名单只决定目标群，`historyFilter(gid, ids)` 默认没有注入，因此无正向历史。该过滤器只收到 ID，不能证明网络历史内容与观察时的内容一致。
* memory-brain 的 SQLite 依据完整 `{tenant,platform,type,session,user}` 和 source 建库；记录包含 evidence，遗忘以 evidence 的 SHA-256 tombstone 表示，读取需同时检查其他后端、撤销、受管存储状态和协调锁。`filterCandidates` 只排除已遗忘证据，**不证明候选已被观察**，不能单独用于授权远程历史。来源内容缺少同 scope 原始事件绑定的旧记录不可视为已认证群观察。

## 可实现的安全路径

1. 单独提供明确 opt-in 的群桥认证 OneBot 配置，并复用现有认证连接实现，不要求启用 durable chat；连接断开、认证失败或实例变化时拒绝。须明确 operator 对本机进程/上游身份的信任，不能声称 QQ 提供密码学证明。
2. 在 OneBot 私有解析路径记录群事件的不可伪造进程内证据，绑定实际连接实例、机器人账号、规范 group ID、发送人、消息 ID 和精确原始内容；快照时重新验证，拒绝对象复制、突变、不完整和非规范 ID。群级操作权限必须来自独立可信本地配置或可信授权工作流：显式绑定 group ID、操作者和读权限；白名单仅用于目标配置。
3. 将经验证的实时群观察写入同群 scope 的 SQLite，来源明确为 `qq-group-message`、evidence 采用一致且不含糊的 `onebot-message:<canonical-id>`；实际内容也必须与此 evidence 在同一记录绑定。不能将仅 ID 匹配的远端返回文本当作观察内容；冲突、遗忘、撤销、缺失、损坏或无授权一律拒绝。不能自动导入旧的无来源群历史。
4. 由本轮已认证入站消息和本地策略生成不可由模型重建的短期闭包，传经 `handleTurn` → `Brain` → 群桥；闭包校验操作者、来源会话、目标群和时效。明确群内读本群与私聊跨群读的授权策略；`read_group_chat` 不应自行根据模型给定的群号签发能力。禁止同群 scope 之外的信息及未受权多群枚举。
5. 直接读取 SQLite 中已证实观察更简单；若查询远程历史，只能返回与已观察原文及来源一致的记录，并在同一遗忘协调边界中检查 SQLite tombstone。生成结果后还需持有或复核对这些证据的依赖直至外发，避免生成和发送间遗忘竞态。断电恢复、备份回滚无法仅靠本地标记证明完整性，按现有受管存储人工复核规则处理。
6. 离线集成测试应使用真实 OneBot WS 入站解析、真实 Brain 工具循环、临时 SQLite 和模拟 OneBot：覆盖授权正向、未授权/跨群/冒充/拷贝/突变、错误连接、相同 ID 内容冲突、遗忘及生成中遗忘、无历史、数据库故障、不同群隔离和恢复后复核。测试数据和凭据全部合成；不连接生产设备或接口。

## 尚缺

目前群观察 SQLite 写入、群 scope 遗忘管理、认证群快照、操作者授权配置和跨 Brain 的短期能力均未实现；因此正常授权的群桥历史仍未恢复。群成员普遍授权、共享群内数据至私聊的政策亦须由明确的本地授权规则规定，不能从群白名单推导。
