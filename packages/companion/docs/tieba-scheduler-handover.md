# 贴吧只读调度：隔离接入说明

当前未接入运行时，默认关闭；没有内置贴吧数据源，也没有发帖、点赞或登录能力。测试仅使用模拟数据和模型，不代表真实访问或阅读。

`createTiebaScheduler({enabled:true, reader, brain})` 接受现有 `createTiebaReader` 和实际 `brain.complete`；`start()` 首次等待一小时后按完成后间隔调度；`stop()` 防止尚未开始阅读的决策继续，但不会终止已经运行的 source/reader。决策失败、拒绝或重叠时不开始读取。生产接入前需要在适配器和 reader 中实现 AbortSignal 及停止屏障，避免停止后仍有后台访问或落盘；现有 reader 的 Promise.race 超时也不能取消底层操作。

可信的只读 source 须独立校验实际页面、论坛归属、重定向、完整内容、挑战页，并只允许目标域名的安全请求；reader 仅校验适配器返回值，调用方不能把模拟或任意注入数据当作真实阅读。reader 当前仅遍历列表头部候选，没有在阅读前按标题选择；模型阅读后才决定继续/跳过/保存。兴趣记忆的原文可能包含隐私或恶意指令，需配置数据保留/删除、访问控制，并评估去重和数据大小。

私聊接入时仅从可信 OneBot 事件取得 channel、senderId 以及配置的 ownerId，调用 `recallTiebaForOwner({reader,query,channel,senderId,ownerId})`。禁止让模型或用户文本提供身份。返回的标题和正文均为不可信内容，使用低权限上下文隔离、长度限制及明确的数据标记；不得插入 system/developer 指令，也不得让这类材料调用工具或成为对外发布依据。仅隔离提示不能保证抵御提示注入，生产接入前应补充真实 brain 路径对抗测试，阻止私人信息泄漏。其他人私聊和群聊不得召回；不要声称读取过未核实来源的内容。

安全限制：源数据完整性由 adapter 的可信承诺而非密码学证据保证；本模块没有生产源、真实模型、实际聊天链路或外网端到端验证，不能视为已上线。仓库中的既有 reader 明文保存全文，权限只对新文件设置；已有文件权限不自动修复，raw recall 也没有上下文预算及提示注入免疫。建议完成以上工作并核验后，再由主集成者决定是否启用。
