# Isolated durable tool-effect executor

`src/chat-durable-tool-effects.js` is a default-disabled building block, not production chat wiring. Use a **dedicated** `EncryptedChatJournal` and explicitly pass `enabled:true`; the existing `handleTurn`, Brain tool loop, queue, media, state and delivery remain unchanged. This does not make durable chat production-safe.

The trusted caller supplies an immutable, stable `(session, turn, call)` identity, exact JSON args and a trusted allowlisted tool registry. Each tool receives a detached JSON copy and must explicitly return `{status:'completed', result:<JSON>}` only after its effect's outcome is actually established. An ambiguous result, exception, invalid result or process failure leaves the persisted `unknown` marker. The executor commits this marker before calling the tool; no same-session call is allowed while any marker is unknown, including after reopening. A completed identical call returns its saved result without executing; reused identity with different tool/arguments fails. Completion-save failure is uncertain, so the journal itself fails closed. No automatic or manual unknown resolution API exists here. A success flag is only as trustworthy as the implementation returning it; transport acceptance need not mean recipient delivery.

The caller must persist and replay a stable invocation transcript, not regenerate call IDs from nondeterministic LLM output, and must journal *every* effect before execution (including non-tool state changes, sends, voice and media). A model-generated tool-call ID is not in itself a durable idempotency identity. This executor cannot force unwrapped code to use it, cannot authenticate ingress or establish delivery semantics, and is not an atomic transaction with an external service. Same-UID callers, the registry, journal directory and encryption key are trusted. `EncryptedChatJournal` uses cooperative local locking and fsync/rename and has no distributed fencing or rollback protection; stale-lock handling requires an independently verified stopped writer. Do not enable production integration without resolving the blockers in `chat-durable-queue-integration-blockers.md` and independent review.
