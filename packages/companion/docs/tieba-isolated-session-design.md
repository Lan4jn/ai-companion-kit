# 贴吧登录会话隔离接入：实验设计（未上线）

## 当前事实

虚拟房间的贴吧入口目前仅打开百度官方网页，不会把该浏览器会话接入小鱼。`createTiebaPlaywrightSource` 每次创建新的匿名浏览器，并使用 Node 端固定 IP 的 HTTPS 请求转发网页资源；请求不带浏览器 Cookie，响应也刻意丢弃 Set-Cookie。即使用户在另一个窗口成功登录，现有阅读器也不会使用它。不要把网页跳转或本实验的合成状态称为真实登录成功。

## 隔离实验

`test/synthetic-tieba-session.test.js` 和 `scripts/synthetic-tieba-session.js` 使用真实 Chromium，但只加载拦截器返回的 `.invalid` 合成页面；登录按钮由合成页面设置固定测试状态，另一页在同一持久上下文中读取后端合成内容。未连接真实百度、未模拟真实账户登录，也未把实验接到生产。浏览器配置使用不可解析的代理、DNS 全拒绝、禁 QUIC、拦截所有请求和 WebSocket；这只是多层防护的局部测试，不能代替网络命名空间/防火墙验证。测试结束关闭上下文并清理目录。

## 可行方案与未解决问题

1. 启动专用低权限 UID/容器及专属网络命名空间、私有挂载和 0700 持久配置目录；仅保留显示、浏览器、必要共享库和该配置目录，杜绝读取现有应用数据和其他账户。单独启动的浏览器配置不是使用者的私人浏览器。
2. 用户通过隔离显示连接官方站点，在同一长期存活的持久浏览器上下文中手动登录；不要抓取、打印、转发或向模型提供密码、验证码、Cookie 或登录页面文本。浏览器配置文件仍包含敏感的登录状态，必须保证隔离、备份和销毁策略。登录状态不是服务端认证成功的证明：须有官方页面或响应上的独立、可核实的账号已登录信号；否则保持未知/失败。
3. 共享上下文内打开专门只读页面供阅读器使用；不能延用匿名 `fetchPinned`，它剥离会话。浏览器出站必须经过强制网络出口代理或防火墙，不仅是 Playwright route：对每个请求和重定向校验官方域、方法、路径、实际解析地址，并固定已验证的公网 IP，限制 CONNECT、DNS、IPv4/IPv6、UDP、WebRTC、WebSocket、service worker、下载和弹窗，认证所需例外单独限定；避免 DNS 重绑定和跳转 SSRF。未知域或操作默认拒绝。不能推断登录实际需要的所有官方域、路径，须在隔离条件下核实。
4. 登录阶段与阅读阶段采用不同网络权限和路由策略，且必须从底层阻断阅读页面发帖、评论、点赞及其他副作用。审查第三方脚本、跨站重定向和退出登录后访问；提取时仅返回正文所需字段并沿用原有论坛及帖子身份校验，不返回账户资料和认证头。读写权限不能仅靠 JS DOM 或浏览器的请求路由保证。
5. 远程交互入口使用有效期短、一次性、并发安全的连接授权；退出、超时、浏览器崩溃均撤销入口并结束显示代理。连接断开不等于登录成功，成功与保存只能由服务端验证；临时文件、进程和代理必须清理。持久会话单独保留，由明确注销/删除动作销毁。需要审查实际 broker 是否正确认证和抗重放，不能拿合成布尔值当真实验证。
6. 用户允许局域网明文，不代表保密：同网段旁路监听、恶意网关或镜像端口可看到屏幕、按键及会话令牌，甚至接管登录。优先使用 SSH/TLS；若仍选择明文，必须只在可信隔离网络短期开启，明确告知风险并限制源地址，但源地址限制不能防旁路窃听。绝不能在日志中记录用户输入或画面。

上线前必须完成真实依赖域和官方登录成功证据研究、受控出站与 DNS 重绑定对抗、浏览器逃逸边界、读写权限、一次性授权并发重放、崩溃清理、持久权限、同上下文实际阅读及失效测试。当前尚无这些证据，不应开启真实账户或宣称已完成接入。
