# 抖音本人接管：当前不可用

**不要启用或尝试接入真实账号。** 当前源码中的生产有头入口无条件拒绝启动；房间的旧版抖音扫码启动接口也返回 503。`douyinHandoff: true` 和 `COMPANION_ROOM_ACCESS_TOKEN` 不能让真实接管可用；不要为了测试绕过开关、复用旧扫码入口或重启服务。工作区源码不一定是正在运行进程的版本。

## 面向交付的最小方案

从登录开始就在隔离显示环境启动小鱼的**同一个有头浏览器会话**，本人在官方页面上完成平台要求的操作；不能将旧无头会话的挑战转移到新窗口。接管完成后，先独立验证登录，再以并发安全的方式决定是否保存候选凭据；不得仅凭页面点击或 Cookie 存在报告登录成功。不收集或在聊天、日志中传递密码、验证码、二维码、Cookie、画面或身份信息。平台拒绝或风控时停止，不绕过验证。

优先满足用户允许的可信局域网免认证需求，但免认证只表示局域网参与者均受信：必须限定真实对端 IP、监听范围及 Host/Origin/Fetch Metadata，禁止公网和跨站访问，单会话单消费者，明确断开、取消和超时的撤销语义。它不能识别个人，明文可被同网段监听或篡改，画面和按键也可能泄露；部署前需明确告知。现有 bridge 要求 Basic 认证和私有来源，不是可直接交付的 LAN 免认证实现，不应简单移除认证。

## 交付阻碍

1. 现有 `douyin-headed-daemon.js` 硬关闭；候选 worker 和组合器是测试专用，测试环境变量不是安全边界。它们未形成经过审查的生产根文件系统、受限身份分配及跨 UID 安全资源交接。
2. 浏览器网络必须通过独立可信 broker 实施最小必要的官方登录目的地及方法策略，隔离私网和其他进程并验证 DNS、重定向、WebSocket 和浏览器后台流量。当前正式候选策略仅允许抖音首页 GET/HEAD，不允许登录 POST；不能猜测或为了凑通而放宽。真实站点跨域资源、登录及平台策略兼容性尚未验证。
3. 现有合成 viewer 和实际手机/输入法不等价；中文输入已发生偶发丢字，触屏、输入法、功能键和验证码挑战尚未在实际用户设备验证。输入可能经短暂的 viewer 代理处理，不能宣称完全不经过中间层或零落盘。
4. 需要安全接入 room 的受控 LAN 入口，保证新登录从接管浏览器开始，且不会落到旧无沙箱 daemon；为正常完成、取消、断线、超时、浏览器及监督器崩溃验证撤销、进程/套接字/临时文件清理与候选凭据提交竞态。
5. 需要真实平台只读身份校验和真实本人设备兼容测试：未经用户操作及授权，合成正例不能证明真实验证码、登录或账号持久化成功。检查过程不得记录身份或凭据。

完成独立安全审查和真实兼容验证前，保持默认关闭；仓库内合成测试和原型只证明有限的实验性质，不是部署说明。当前没有可交付的真实接管链接。另行打开官方站点或 App 也不会自动把登录状态同步给小鱼。
