# memory-brain 撤销回滚风险（未修复）

当前 `.revoked` 标记及 SQLite `adapter_policy` 与数据位于同一恢复域：还原撤销前的整个目录会同时还原两者，旧记忆可以再次被读取。`test/memory-brain-rollback-risk.test.js` 是使用合成数据复现的 TODO 回归；失败是已知风险，不是修复。

## 不可误认为已解决

本地额外文件、追加日志、签名或 HMAC 能提供某些篡改检测，但若文件和验证所需的最新状态可被一起回滚，就不能发现整份旧版的重放；普通本地锁也不能建立独立的恢复域。凭空生成另一份同权限密钥或自动初始化丢失账本会引入伪造、误删或静默重建漏洞。暂不接入生产，也不修改实际数据、配置或服务。

## 安全候选的必要前提

需要独立信任和恢复域提供持久、认证、不可回退的撤销权威，例如受限制的独立服务或具备防回滚能力的硬件，并由运维明确保护、备份、监控及管理权限。未经验证的普通目录不满足此条件。绑定稳定的存储实例身份和规范化完整作用域与来源；对于单条遗忘，还需单独绑定证据标识。防止跨实例重放和未经授权的撤销，避免未经验证的记录影响其他来源。

所有 recall、remember、rankCandidates、forget、cleanup 和 revoke 均需经过权威校验；检索排序及实际返回期间应与撤销按来源线性化，避免检查后并发泄露。撤销必须先持久提交独立权威再清除数据库，只有持久确认后方可报告成功；超时或响应丢失按状态未知处理并以幂等标识重试，不能宣称未撤销或自动恢复。独立权威不可达、身份/完整性错误、实例身份不匹配、状态缺失或回滚时一律拒绝数据访问；禁止自动创建空账本。多进程锁必须有稳定身份且覆盖整个操作，数据库还原也须通过同一协调边界完成，不能依赖可被替换的锁路径。

实施前应审查实际引擎的所有数据出口、权限边界、锁恢复、崩溃写入顺序、文件和目录 fsync、快照回滚、并发及丢失密钥的恢复程序；再用隔离数据验证伪造、删除、截断、重放、部分写入、故障注入、并发与全目录回滚。遗忘操作同样需要独立防回滚记录，否则备份还原可复活被遗忘的单条记忆。缺少可信独立权威时不得声称防回滚。
