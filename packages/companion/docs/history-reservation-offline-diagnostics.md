# Offline history reservation diagnostics (isolated candidate)

Stop all queue and memory writers independently before examining a real incident. The journal lock does not identify its owner; a stale-looking lock is not proof that a writer has stopped. Never remove it on a timer. Preserve the journal, SQLite files and external delivery evidence. No automatic release or reconciliation is provided.

`createMemoryBrain(...).inspectChatHistoryReservations(scope)` requires both normal scope authorization and recovery authorization, uses the existing SQLite ledger and lock only, and returns turn/payload hashes without text; unknown backend and damaged or uncheckpointed SQLite state fail closed. The hashes may still be sensitive correlation identifiers. Treat the result as confidential. The method does not assert delivery or prove that the queue is stopped.

With the actual locked `EncryptedChatJournal`, `inspectReservationBatch(journal,{id,ownerId,scope,store})` validates the main-chat seal, owner, position/ack and scope, and correlates the selected signed batch against the reservation. It returns the keyed journal snapshot, matched/absent/conflict, and **journal-reported** delivery position, not external delivery proof. Missing journal rows cannot be reconstructed from a reservation hash. Inspect real transport evidence independently; rollback of the journal or database cannot be excluded by a signature alone.

Release is deliberately disabled, including for a signed `ready` row: this system lacks an independent anti-rollback authority and an authenticated, durable human confirmation binding external delivery evidence and stopped-writer state. `unknown`, partially delivered, and acknowledged-but-history-pending items must never be freed as unsent. Do not edit SQLite manually or invent confirmations. History-pending recovery remains through the signed acknowledgement and idempotent history commit; no resend. A future release implementation must atomically journal one-item disposition, prevent retry/re-reservation, make audit durable without message bodies, bind independent evidence and queue exclusivity, and test SIGKILL at every cross-store boundary before enabling writes.
