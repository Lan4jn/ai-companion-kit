# 内嵌居室访问鉴权（需运维择机启用）

当前运行中的服务不会因为代码文件改变而自动受保护；本次没有修改运行配置或重启。旧行为保留：不设置环境变量时不鉴权，直接监听局域网并不安全。已有的 Host、Origin 和局域网来源检查不是身份认证。

经用户确认维护窗口后，可为服务设置 `COMPANION_ROOM_ACCESS_TOKEN` 并重启；变量必须是 32–256 个 URL 安全字符（字母、数字、`_`、`-`）。使用密码学安全随机令牌，例如 `node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"`；应在可信终端生成并通过受限权限的服务配置传入，禁止写入仓库、命令行参数或聊天。浏览器打开原地址时用户名为 `room`、密码为该令牌。鉴权涵盖整个服务，包括 `/panel`、`/login`、API、静态资源和 SSE；脚本客户端必须发送 Basic 认证。浏览器可能缓存登录信息；注销需关闭浏览器会话，轮换令牌需重启。令牌须高随机性，服务没有限速或账户管理。

**HTTP Basic 只是编码，不加密。** 即使局域网访问也会明文传输令牌和数据；不要在不可信网络直接使用。优先把服务绑定 `127.0.0.1`，使用校验服务器主机密钥的 SSH 本地端口转发，从自己的电脑访问 `http://127.0.0.1:本地端口/`。服务器上的其他用户/进程仍可能访问本地服务。现有服务没有可信代理支持，不能简单放在普通反向代理后当作已验证 HTTPS；启用 HTTPS 需要另行设计和验证 Host/Origin/代理信任。生产切换前检查所有自动调用方并保留本地管理通道，避免锁定用户。无变量时旧客户端无需更改，但也不受认证保护；启用后未升级客户端将收到 401。

`/login` 的现有扫码及来源限制仍然适用；新增令牌不代表人工挑战接管已完成。参见 [人工验证接管原型](isolated-login-prototype.md)。
