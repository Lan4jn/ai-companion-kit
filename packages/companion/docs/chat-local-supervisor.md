# Supervised local chat channel (experimental, not wired to durable chat)

`src/chat_local_supervisor.py` provides an explicitly enabled Python Unix-stream channel to one child launched by the supervisor. It verifies Linux `SO_PEERCRED` UID and the launched child's PID on the actual accepted socket, retains that connection, and accepts only framed owner messages. The child must speak length-prefixed UTF-8 JSON: `{"type":"message","sender":"OWNER","id":"unique-id","text":"..."}`; replies are `{"type":"send","text":"..."}` and their only positive acknowledgement is `{"type":"result","status":"ok"}`. Calls are serialized. Malformed frames, disconnects and ambiguous sends fail closed; unknown sends are not retried. IDs must be stable upstream message identities; this channel alone does not deduplicate or persist them.

This is a building block, **not a completed live durable-chat integration**. No OneBot adapter, trusted message provenance bridge, safety-filtered output integration, or durable journal hookup is supplied. Existing live durable chat still requires pinned WSS/HTTPS and ordinary chat is unchanged. The Python API itself does not apply the application's full output privacy or tool-artifact filters. Do not connect it to real accounts until these gaps are resolved and independently tested.

The supervisor authenticates the local process connection, not the QQ sender or its upstream: the child attests the `sender` field. An arbitrary HTTP or LAN origin must never be elevated to that role. `SO_PEERCRED` does not isolate processes sharing a UID, prevent descriptor passing, or protect against a malicious same-UID process. Protect the directory and trust all same-UID code. The child's environment is inherited; use a dedicated least-privilege runtime before deployment. The parent must explicitly construct the class with `enabled=True`; nothing starts by default.

Synthetic check: `python3 -m unittest test/chat_local_supervisor_test.py test/chat_unix_peer_gate_test.py`.
