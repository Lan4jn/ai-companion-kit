# OneBot authenticated ingress candidate (disabled)

`OneBot` accepts an optional `ingressAuthentication` object with `enabled: true`, a CA PEM Buffer, a lowercase SHA-256 leaf-certificate pin, and an ownerId. It uses a fixed WSS URL and independently checks the server certificate chain, hostname and pin on each connection. The server is trusted to assert QQ event identities: TLS does not authenticate individual QQ senders independently. The TLS terminator and its upstream must be controlled and protected; an untrusted proxy, leaked private key, compromised OneBot or untrusted code in the same process defeats this boundary. No endpoint or credentials have been validated for deployment.

`createAuthenticatedOneBotIngressCandidate` is separately opt-in and accepts only unmodified owner-private messages from that verified connection. It writes data-only snapshots, derives an owner-scoped sealing key distinct from the legacy parser-only candidate, and does not restore event or tool privileges. It is not wired into production and its separately derived seal key is intentionally incompatible with legacy recovery/formation sender code. A complete authenticated formation and recovery chain plus endpoint/key provisioning, independent security review and deployment verification are required before enabling it. Legacy transport-bound candidates remain parser-only and must not be treated as authenticated ingress. No production configuration was changed.
