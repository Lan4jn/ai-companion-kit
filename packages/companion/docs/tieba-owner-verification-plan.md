# 贴吧本人接管与身份正例：最小安全验证方案（未实现）

## 当前结论

当前没有可安全交付真实账号的贴吧本人接管服务，也没有经过官方正例验证的身份协议。现有 `tieba-mock-handoff.js` 只运行虚构登录和虚构身份，不能接真实账号；`createTiebaCandidateFactory` 是依赖注入接线点，不是隔离浏览器或官方验证器。保持生产候选默认关闭，不改配置、不重启、不读取或让用户提供密码、验证码、Cookie、令牌或二维码。遇到平台风控或验证墙停止，不做绕过。

百度官方[账号注册、登录说明](https://ai.baidu.com/ai-doc/REFERENCE/Tktjypljq)称百度账号可用于贴吧及其他产品，但并未规定可核验贴吧登录状态和稳定账号标识的接口；智能云 access_token 也不能作为贴吧身份凭据。现有 `/dc/common/tbs` 未证实正例或账号标识，匿名调用还曾遇到 HTTPS 到 HTTP 的重定向，不能携带凭据降级或据此判定 online。

## 需要实现并评审的交互

1. 本人明确同意后，在专用非特权 UID、私有临时目录和隔离桌面启动全新有头浏览器；浏览器必须从一开始就是接下来验证与读取所用的同一个 context。限制本机进程、远程桌面及浏览器控制接口的访问；不声称能防止 root/宿主观察。禁止记录画面、输入、凭据、网络正文和完整 URL 查询串。不可把当前同 UID 的合成 Xvnc 实验当成生产隔离。
2. 在独立、认证并加密的本人操作通道中完成一次性、短时、单消费者接管；验证服务器身份，限制来源，禁止复用无认证面板、明文 LAN 或 URL 中的令牌。关闭页面、断线、撤销、超时、服务崩溃时关闭浏览器、撤销能力并清理临时文件；受信监督器负责崩溃清理。必要时本人在官方页面自行登录，但对风控停止，不请求其向助手传递任何秘密。
3. 登录期必须具备独立审查过的网络边界：按阶段明确 HTTPS 官方目标、方法及用途，DNS 解析后逐跳验证公有地址并将连接固定到已验证地址，禁止降级、私网及未经允许的跳转，并防止 QUIC、WebSocket、Service Worker 等旁路。现有登录壳资源分类不是防火墙，也不是完整登录依赖清单；不能因列表缺失而扩大为任意百度域或任意请求。真实登录所需网络依赖尚未知，此阶段因此仍是阻塞项。
4. 接管就绪与身份认证必须分成两个阶段。`provider.start()` 目前立即调用验证器，未登录时会关闭会话，不能在页面显示前直接调用它并假定会等待本人登录。应先创建和维持有头 owner session，让本人操作；然后由本人发起“检查登录”，仅触发不暴露秘密的验证。检查失败不报告成功，取消或断线撤销同一会话；候选连接时明确处理所有权、并发取消和重复启动。不能让用户点击“完成”直接产生 online。
5. 身份方案先取得官方协议或明确可审查的官方 HTTPS 响应证据，再验证匿名负例、本人已登录正例、失效/退出负例和切换账号负例；请求应使用同一 context 与严格网络边界。验证响应来源、TLS、状态、格式、错误及风险信号，比较经证实稳定的账号标识，而不是昵称、DOM 任意文本、Cookie 存在或布尔按钮。缺字段、重定向、风险、格式变化、网络错误均为 unknown。若找不到具有官方依据的身份协议，保持禁用，不把一次页面结果推断为认证协议。
6. 消费期先撤销接管输入、关闭登录页及其进行中的请求，再切换到单独审查的只读网络策略，并证明不存在竞争窗口；复用同一 context，不复制或打印凭据。要证明重定向、DNS 重绑定、非只读方法、私网、WebSocket 和浏览器后台流量被阻断。现有候选传输只转发 `tieba.baidu.com` 的 secure host-only Cookie，不能假设它支持百度跨域登录；只有获得授权并验证最小必要凭据范围与边界后才能改变。
7. 对读取前后身份重新核验、账号变化、断线/取消/超时与验证或读取并发、部分启动失败及监督器崩溃逐项做负例，确保无结果泄露、无旧凭据覆盖、进程和 socket 被回收。合成端到端证明只能覆盖接线与生命周期；真实账号正例必须由本人授权操作并记录不含秘密的最小结果，且不能凭测试声明生产安全。

## 与本人实际交互前的阻塞

需先实现并验证以上隔离、加密操作通道、受控出口、阶段切换和经过可信依据支持的身份验证器；目前这些条件未满足，所以不启动真实接管、不要求本人登录。完成后再单独说明数据边界、取消方式及可能遇到风控即停止，征得本人同意。最终只能公开 `unknown/online` 等必要状态及无秘密的安全测试结果，不保留账号身份值、截图、Cookie 或请求正文。
