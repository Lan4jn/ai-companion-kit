# 可选的 memory-brain 私聊记忆

> 本机核心源码与公开上游历史版本的内容已匹配，但该历史版本的许可声明相互冲突；详见 [来源审计](memory-brain-provenance.md)。候选采用受信任进程、精确作用域与来源及受控恢复契约，操作步骤和不可检测的回滚限制以 [运维信任契约](memory-brain-trust-contract.md) 为准。生产继续保持关闭。

默认关闭；仅在明确设置 `memoryBrain.enabled: true` 后运行。该开关没有修改当前配置。启用后只处理由 OneBot 事件解析器创建且安全字段未更改的主人 QQ 私聊、单条纯文本且带消息 ID 的消息；群聊、多消息批次、引用、媒体、探测和 dry-run 不进入该路径。回复发送确认成功后才记录原始用户消息；部分发送失败、未确认、内容被拦截或无回复不记录。新消息以 `qq-private-message` 和 OneBot 消息 ID 为来源和证据；不导入旧账本。

适配器调用真实 `MemoryEngine`，默认从本机 `/root/memory-brain/memory_core` 加载、使用 `/usr/bin/python3`（须能导入 numpy），无外部向量 API。跨机器部署时，可在明确启用的候选配置中设置 `memoryBrain.engineRoot`（包含 `memory_core` 目录的绝对路径）和 `memoryBrain.python`（解释器绝对路径）；这两个路径及其依赖必须由可信管理员控制，加载 Python 代码等同于执行代码。不要把它们设为用户输入。子进程不继承业务密钥或 PYTHONPATH，但不是沙箱。每个租户、平台、会话类型、会话、用户和来源组合对应独立数据库；授权先于数据库访问和检索，缺来源或证据的数据库拒绝检索。数据库目录权限 0700，文件 0600。检索或写入失败时保留原有聊天回忆逻辑。不要将此目录指向旧记忆库，也不要与其他系统用户共享；这不是抵御拥有相同操作系统账户权限的攻击者的沙箱。

## 互联网兴趣候选索引

相同开关和 QQ 私聊门槛下，对原有来源召回已允许的候选，使用真实核心在内存中临时建索引排序；不把互联网内容写入通用私聊数据库，也不持久化第二份记录。贴吧仍受原读者的 30 天期限、地址、内容筛选和开关约束；番茄仅收带原始 OCR 与匹配指纹的记录；B站仅收原观看证据校验通过的观察，并沿用原主人边界。每次重新从原来源召回，所以原记录删除或过期后不会通过这个索引复活。索引结果附来源与证据，并提示 OCR/ASR/画面理解不确定、外部文本不是指令。它只能排序现有查询已召回的候选，不是全网采集或语义回溯；暂未接抖音、普通网页等其他来源，红果未接入。不开启服务、不自动变更配置。

## 启用与许可证审计

本机 `/root/memory-brain` 副本没有 Git 元数据或顶层 LICENSE/COPYING，README 和 pyproject 未声明许可证。已通过 30 个文件的 Git blob 哈希匹配到上游 0.2.1 历史提交，但该提交的仓库根目录 LICENSE 与 README 中 AGPL 声明存在冲突；详情见[来源审计](memory-brain-provenance.md)。部署或分发前须由权利人明确适用许可，并核验 Python、numpy 及其他依赖的许可证。适配器本身也只接受布尔值 `true`，字符串 `"true"` 等不会启用。

依赖缺失、存储权限问题或来源标签错误会使新增记忆功能退回，聊天不依赖该功能。当前未迁移旧数据；更换机器须部署 memory-brain 与 Python 依赖。检索为本地关键词/引擎排序，未配置语义 embedding。

## 生命周期操作（候选接口，不自动运行）

适配器提供 `forget(context, {source, evidence})` 和 `revoke(context, {source})`，均先按完整作用域和来源授权。单条遗忘会在同一作用域与来源的数据库中保留证据摘要墓碑，阻止相同证据的消息重投或重启后重新写入；墓碑不含消息正文，但并非独立防回滚权威，恢复旧备份仍须按运维契约重新执行遗忘。升级前已遗忘的条目没有自动补建墓碑，须依据可信记录重新执行遗忘。外部候选排序也按同一作用域、来源和证据摘要过滤，但其他原始来源召回路径不受此墓碑控制，仍须在原账本同步删除。跨进程同一来源操作由文件锁串行化，排序也在锁内检查撤销；撤销后拒绝此来源的数据库访问和外部候选排序。聊天接线要求 `memoryBrain.authorizedSources` 显式列出每个来源，缺省拒绝。撤销标记同时保存在独立文件及数据库；仅恢复旧数据库不会复活撤销。**若整个目录包括标记也被回滚或删除，无法抵御复活**；生产恢复须先从独立、不可回滚的权威撤销账本重新应用撤销，目前尚无此设施，不可声称支持全目录恢复安全。

`createMemoryManager` 是未接线的受控管理 API，要求显式开启且同时提供独立的 `authorizeManagement(operation, input)` 和适配器 `authorize`，都必须严格返回 true；提供 `forget` 和 `revoke`，只返回成功标志，不返回原始记录或来源。调用者负责认证管理主体并在受信边界注入授权函数，不得暴露给普通聊天或将不可信输入当授权；目前没有生产管理端点。撤销仅覆盖本适配器的记忆及候选排序，不删除外部原始来源，也不阻止现有其他召回路径读取该来源。

默认保留期至多 30 天，适配器调用可设置更短的 `retentionMs`；每个来源持久化其最短保留期，后续较长配置不能延长。每次访问该作用域来源时先清理过期记录。**这是惰性过期，不是定时后台清理**；无人访问时文件仍可能保留，尚不能满足严格到期自动删除。接口未接入管理界面或聊天命令，备份策略、密钥和恢复授权流程尚未实现；不要对生产数据试运行。删除是逻辑删除而非安全擦除，SQLite 空闲页、WAL、备份和其他系统可能保留副本。

本机 `pyproject.toml` 的项目名为 `memory-core`、版本为 `0.2.1`；已通过内容哈希找到匹配的公开历史提交，不是仅凭同名或版本推断。历史许可条款仍有冲突，保持现有关闭状态，直至权利人明确授权，参见[来源审计](memory-brain-provenance.md)。可通过隔离测试验证：`node --test test/memory-brain-lifecycle.test.js test/memory-brain-core-boundary.test.js test/memory-brain-chat-wiring.test.js test/memory-brain-adapter-isolated.test.js test/memory-brain-interest-rank.test.js test/memory-brain-interest-chat.test.js`。
