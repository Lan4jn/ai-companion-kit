# 贴吧真实登录与会话接入：公开证据和上线门槛

状态：仅匿名公开资料核验；未登录、未扫码、未持有真实账号，也未测试真实认证后响应。**真实会话接入不可启用。**

## 官方资料能够证明什么

- [百度用户协议（二、3、4、8、17）](https://passport.baidu.com/static/passpc-account/html/protocal.html)：百度统一账号可跨产品使用，其他产品首次使用时**可能**同步登录状态；不同设备及风险情形可要求额外验证；禁止绕开登录与使用规则。不能由此推断新浏览器、另一进程或贴吧一定同步登录。
- [百度官方登录入口](https://passport.baidu.com/v2/api)：匿名页面为百度账号登录页；公开搜索索引显示账号密码、扫码及风险验证界面，但该静态提取只返回标志，不能据此推断某次登录流程或成功结果。
- [贴吧隐私政策](https://tieba.baidu.com/tb/cms/tieba-fe/tieba_promise.html)：不注册或登录不妨碍使用大部分业务；具体功能仍可能有限制。此声明不是任意接口或自动化采集授权。
- [贴吧协议 8、9.7](https://tieba.baidu.com/tb/eula.html)：内容、数据、复制及接口开放均受协议、权利和平台决定约束；上线前需确认用途、授权、隐私与留存是否合法合规。
- [贴吧开放 API 介绍页](https://tieba.baidu.com/tb/zt/tiebaapi/index.html) 宣称可申请内容接口及“贴吧账号登陆发贴接口”，但页面版权为 2014，未给出当前会话身份核验端点、请求/响应契约、稳定主体字段或现今可用性。页面列有申请咨询邮箱，但我们未联系、未申请，也不能假定该渠道仍有效。这是待确认线索，不是可实现的身份正例，也不授权发帖。
- [百度开放服务平台 OAuth 介绍](https://openapi.baidu.com/ms/oauth) 描述统一身份认证及跨应用授权，但没有证明任何 OAuth 身份与本阅读器中的贴吧浏览器会话为同一主体。[百度开发者中心用户提问](https://developer.baidu.com/question/detail.html?id=173) 提及获取百度 UID 的调用，但为用户发帖而非接口规范，不证明端点当前有效，更不证明贴吧会话已登录。不可将百度 UID、AI client_credentials token 或 OAuth 授权等同于贴吧会话身份。
- 本次未找到可公开核验、受支持的贴吧“当前账号登录状态”API 契约、真实登录后字段、会话 TTL、刷新机制或可用于第三方只读访问的正式 API 授权。现有页面内部接口即便可访问也不等同官方稳定 API。`verifyOfficialTiebaIdentity` 必须维持 unknown，任何合成数据不能作为真实正例。

## 现有系统的隔离事实

`src/tieba-playwright.js` 新建匿名浏览器，`fetchPinned` 的请求不转发浏览器 Cookie 且不转发 Set-Cookie；另一登录窗口不会自动给现有阅读器认证。`test/synthetic-tieba-session.test.js` 是 `.invalid` 合成站点，不能证明百度认证。阅读数据中吧名及帖子 ID 验证仅证明内容身份，不证明登录。

## 未来接入验收规范（设计，不代表已实现）

1. **用户本人授权和操作**：在隔离的专用低权限浏览器上下文访问官方登录页，由本人完成任何账号、扫码及额外校验；绝不采集、转发、记录密码、验证码、Cookie、登录页面截图或网络日志，不绕过挑战。交互入口要求身份认证、短时单次授权、保密传输；显示服务和浏览器进程须隔离于普通 agent，同 UID 与 root 仍有观察风险。
2. **证据契约未确定，默认 unknown**：必须先得到百度公开支持的贴吧当前会话身份/状态机制，或在获得授权后通过真实受控验收确认可信官方页面/响应的可重复语义。使用同一浏览器上下文对精确 `https://tieba.baidu.com` 源发起经核实的只读状态检查，验证最终 origin、路径、TLS、响应成功、无挑战和有明确的登录态正向语义；禁止把 cookie 存在、用户名任意文本、跳转、匿名页面成功、用户确认或 fixture 当认证证据。页面 DOM 不受信内容或仅源相同都不足以证明身份；如无法建立语义与信任链，则保持 unknown。不得存储或输出用户身份原文，只输出最小状态。
3. **生命周期**：初始 `unknown` → 用户操作 `authenticating` → 经上述独立证据 `authenticated`；未确认、无法访问、验证页或风控均不冒充未登录或成功；明确官方未登录证据可标 `unauthenticated`，明确认证过期可标 `expired`。超时、崩溃、重启、证据过期、网络错误切回 unknown 并停止读取，验证通过后才能恢复。无公开 TTL 时不设声称代表百度有效期的固定值；应用可设保守本地新鲜度上限，每次敏感操作前重验。退出/撤销时关闭代理、浏览器并清除本地 profile；本地删除不等于百度服务端退出，服务端退出需用户走官方流程并另行确认。
4. **同一受限会话**：认证与消费需经确认的同一隔离持久上下文，采用浏览器自身的正常 cookie 规则，不将 cookie 注入当前匿名 `fetchPinned` 或传给模型；注销、过期、挑战立即停止，不自动重试绕过。持久化需要用户明确许可，profile 0700、禁共享/备份及最小留存，重启残留须受监管清理；临时交互结束和永久删除是两个明确的操作。
5. **分阶段默认拒绝出口**：登录阶段与阅读阶段分别审计精确主机、HTTPS 端口、方法、路径、参数和跳转；不得允许整个 `*.baidu.com` 或 `*.bcebos.com`。`passport.baidu.com`、`tieba.baidu.com` 是官方入口，不代表已知完整认证依赖；现有匿名资源白名单也不能直接作为登录白名单。实际新域、第三方内容、弹窗、重定向未知时阻断并报告，不猜测放行。网络命名空间/强制代理只允许代理出站，检查所有 DNS 答案为公网并把验证 IP 固定到实际 socket，同时处理 IPv4/IPv6、DNS 重绑定、重定向、直连、QUIC/UDP、WebRTC、WebSocket、service worker、下载；禁止非预期代理绕路。
6. **只读必须底层可执行**：按已核实路径与方法逐条允许而不是仅禁 POST（GET 也可能有副作用，POST 也可能是只读），绝不放行发帖、回复、点赞、关注、签到、私信、退出等写操作；TLS CONNECT 隧道只能看到目标而不能检查 HTTPS 路径/方法，因此仅靠普通 CONNECT 域名白名单或 Playwright route 不能证明只读。必须用可验证的隔离架构与可信请求执行器强制所有网络出口和请求语义，兼容官方 TLS 并经专项测试；若不能做到，拒绝上线。登录阶段与只读阶段权限切换期间阻断并发、存量连接、后台任务和 service worker，无法确保则销毁上下文，且不能假装销毁后会话可无损续用。
7. **测试门槛**：离线对登录态伪造、错误页、过期、撤销、跨源跳转、证据陈旧、响应格式变更、伪造 DOM、重绑定、公私混合解析、IPv6、CONNECT 绕过、UDP、持久连接、service worker、写请求、挑战、异常终止和清理进行负向回归；再经用户授权完成真实账号正/反态及只读访问验证。任何一项缺失均不可标记真实接入成功。
