# 网页研究 unknown 离线人工对账

工具仅限隔离工作区；不得连接生产数据、消息、账号或设备。只有确认原研究进程及所有可能的执行者已停止且不会恢复时才能操作。工具不会执行搜索或自动重试；锁仅保护持久存储事务，不能证明外部任务已停止。

1. 授权操作人从隔离存储中单独确定确切文件、goal ID、desire ID、原话题；不要复制正文到命令行或证据引用。建议先在私密终端关闭 shell 历史，避免话题出现在 shell 历史及进程参数中。
2. 只读审计（不创建锁/文件）：
   `python3 tools/web_reconcile.py audit --store /绝对路径/目标文件 --goal GOAL_ID --desire DESIRE_ID --topic '原话题'`
   输出只有 canonical 文件路径、两 ID、规范话题哈希、整个文件内容的版本哈希与 unknown，不输出正文。话题哈希可能被字典猜测，不应公开。
3. 人工调查独立的一手证据和执行进程，验证目标身份、状态及时间线：独立证据足以证实实际完成时选 `completed`；足以证实执行已终止且不会再完成时选 `terminated`。脚本退出状态、模拟回执、单纯缺乏结果均不是独立证明；证据不充分、仍可能在运行或存在歧义时保留 unknown，不执行下一步。
4. 使用审计返回的精确 version、同一目标和话题，指定操作人标识和**不含正文或秘密的内部证据登记编号**（限字母数字 `_.:-`），在真实终端执行：
   `python3 tools/web_reconcile.py resolve --store /绝对路径/目标文件 --goal GOAL_ID --desire DESIRE_ID --topic '原话题' --version VERSION --outcome completed --operator OPERATOR_ID --evidence-ref CASE_ID`
   仔细阅读终端确认提示，核对后逐字输入要求的确认。终止时将 outcome 换成 `terminated`。将操作人、证据编号、结果及旧版哈希原子写入存储事件；完成/终止分别关闭 goal 和 desire。此操作释放该话题的后续 claim，不会主动搜索。
5. 文件变化、锁竞争、操作失败或进程中断时**不要自动重试**。尤其替换文件后目录 fsync 失败或崩溃，结果可能已生效；先重新读取存储并核对事件、独立证据和实际运行情况，再决定是否需另行人工处理。审计只接受 active/active 目标；已关闭的目标需要用安全的只读存储检查核对，不可按旧版本重放。

安全边界：此工具依赖操作人真实调查，不会验证证据的真实性、操作人身份或脚本生成的伪造 TTY；不得把本地合成测试或工具输出当作真实执行证据。同 UID 进程可直接修改文件、替换锁、伪造终端和证据或调用 Python API，flock 是协作锁而非授权边界；目录必须由可信主体保护，所有写入者必须遵守 goal-core 同一 canonical `.lock` 协议。audit 是瞬时快照，执行时重新持锁验证整个存储版本与目标，任何变化均拒绝。本工具不提供独立于本机同 UID 的身份认证、不可篡改审计或恶意并发保护。
