# memory-brain 运维信任契约（候选，生产默认关闭）

本机源码已匹配到公开上游历史提交，但该提交许可声明冲突，详见[来源审计](memory-brain-provenance.md)。保持 `memoryBrain.enabled` 关闭，不复制、分发上游核心或更改生产配置。此实现只提供可选功能，不构成验收或防回滚保证。

## 明确信任边界

由授权运维控制服务进程、配置、引擎代码、私有目录及所有备份/恢复；同 UID 可绕过本接口、改代码或直接读数据库。`trustedProcess: true` 是运维的明确授权声明，不是身份验证或自动检测机制。需要同时明确设置 `enabled: true`、`trustedProcess: true`、`trustedScope`（tenant、platform、type、session、user 五项精确字符串）以及 `authorizedSources`（显式来源数组），且仅 QQ 主人私聊符合既有消息验证时才会使用。任一条件不符关闭；不得从聊天内容赋权。调用失败保留普通聊天回忆路径。

正常持久化目录必须先由授权管理员通过 `node scripts/memory-brain-managed.mjs` 的 init 创建；仅接受绝对规范路径和私有父目录，拒绝已有目录。正常启动及重启均可使用同一目录，按精确用户作用域和来源限制访问。不要将它指向旧数据库。

## 离线备份和恢复

停止全部读写、维护及恢复进程并确认退出；在此期间禁止并发启动。使用一致、可信、私有的备份，包含整个已初始化存储目录；不要备份活跃 SQLite 数据库文件。隔离保存独立可信的撤销和单条遗忘记录；本功能不替你建立这些记录。备份需要恢复时仅允许管理员在私密、已认证的本机终端运行 `node scripts/memory-brain-managed.mjs` 的 restore，将备份复制到**不存在的新目录**。先写入 incomplete 状态，完整复制并持久化后切换为 review；中断或失败无法直接复核启用，须排查并重新恢复到另一个新目录。review 状态下自动读写和候选排序均拒绝。

保持应用停止，由授权管理员使用独立可信记录逐一核对所有受影响作用域、来源和证据，重做备份之后的全部撤销及单条遗忘，核实结果；缺少完整历史则不得授权。可使用现有离线 `scripts/memory-brain-admin.mjs` 对恢复目录进行必要管理，注意其绕过本契约，必须由同一可信管理员执行。完成后使用 managed 工具的 review 明确输入确认短语，才切换 ready；再由运维安全切换到该目录并启动。TTY 不是身份认证，工具不可暴露给聊天、共享终端或网络。操作失败不得假定已完成。

**限制：绕过受控工具直接将旧备份整目录原位回滚，连同状态文件一起回滚，程序无法检测；旧记忆可能复活。** 同 UID 篡改、非协作进程、授权检查与恢复并发亦不受保护；此方案依赖运维纪律，不是独立防回滚账本。需要自动检测以上情况须另建独立、不可回退的可信权威。不得将本地标志、inode 或签名称作绝对防护。
