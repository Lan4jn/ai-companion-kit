# B站评论提交对账边界

评论发送前按 B站账号数字 UID、视频数字 aid、操作（主评论或回复及 root）原子创建不可覆盖的账本记录；写入并同步文件和目录失败则拒发。主评论网页和 API 共用键，不按文本区分。原记录始终保留为 `unknown`、永不自动重试或删除；楼中楼直接 API 有严格回执时可经独立公开核对追加 confirmed 证据，详见 [隔离实验说明](bili-comment-reconciliation-experiment.md)。记录含文本 SHA-256，供持有原文的人核对，不存账号 cookie 或评论原文。

人工处理：停掉所有会写该账本的进程后，保留账本原件，按账号、视频、回复目标、时间和原文核对 B站实际评论，记录证据、操作者、判断和时间。不能确认是否发出时保持封存，不得重发。若确认未发出，只有人工明确授权后，才可将对应记录移到账本目录外的受保护审计归档，再恢复进程；此操作允许下一次新决定发送，不自动发送。若确认已发出，保留记录永久阻止重复。若记录损坏、账号或目标不明，也须保持封存并人工调查。人工归档及证据管理目前是运维流程，不提供自动对账或解锁接口。

账户需提供 DedeUserID；网页主评论还必须提供 aid 且页面实际加载的 aid、bvid 与指定目标一致，否则拒发。账本必须放在支持本地原子 O_EXCL 和 fsync 的持久文件系统上，所有进程必须共用同一目录；跨机器不共享该目录、手动删除记录、备份回滚或文件系统不保证这些语义都会破坏防重。迁移前须停写并保留全部账本。
