# Memory-brain lifecycle candidate (not enabled in production)

This is a candidate, not an acceptance or production deployment. The upstream memory-brain license/provenance remains unresolved. Keep it disabled until reviewed. Restoring old databases and revocation markers can resurrect deleted data: anti-rollback is not implemented. Backups require a separate trusted revocation/retention strategy.

## Scheduling

`createMemoryMaintenance({enabled:true, brain, scopes, intervalMs, onError})` requires explicit, trusted configuration and a brain configured with an authorization callback permitting `cleanup` for each exact scope/source. `start()` installs the timer; no timer is installed by default. No automatic production startup is wired. `stop()` cancels the timer and drains an in-flight pass. Failures are passed to `onError` without private details; monitor them externally. Each pass works only on the supplied scope/source list, does not discover databases, and does not create absent ones. Keep the list current from a trusted authorization source; do not derive it from remote input. Cleanup serializes with existing workers via their per-database lock. Missing scopes are skipped. Revoked scopes fail closed; a failing scope stops that pass, so monitor and remove revoked scopes from the list. The existing retention setting and persisted minimum apply; no other maintenance job should modify these files without the same locking protocol.

## Local management

Run `node scripts/memory-brain-admin.mjs` from an authenticated, trusted OS-user terminal. It requires an interactive TTY, explicit scope/source, action and confirmation. It uses the OS account and possession of the private directory as the administrative trust boundary, not the chat owner's web session; it intentionally grants that local administrator authority over the specified scope. Never expose this CLI through a web route, a shared terminal, remote command proxy, or unauthenticated LAN service. TTY checks alone are not authentication. Input, including evidence, is visible to the terminal operator; use a private session. Existing directory owner and permissions checks still apply. The tool does not list or read memories. Revoke is permanent and creates a persistent denial marker, even for a scope with no existing records. A failure can have partially applied changes; inspect through a trusted administrative workflow before retrying. Default engine location is `/root/memory-brain`; no production settings are changed by this candidate.
