# Durable batch state machine — isolated candidate

`chat-durable-batch-candidate.js` is an experimental API over a dedicated `EncryptedChatJournal`, not a production queue. It rejects journals belonging to the older candidate and is not wired to ingress, transport, configuration or recovery. It takes synthetic JSON-compatible inputs, not trusted OneBot capabilities. The caller supplies exact output segments and must only report `{status:'delivered'}` when one complete segment is explicitly confirmed. Other or contradictory outcomes leave it unknown. A claim object is usable for completion only in the instance that issued it; after a crash it cannot be completed or automatically resent. No human reconciliation facility is provided.

Acceptance, batch formation, claim and each acknowledged segment are each an encrypted whole-journal atomic save using the existing journal's fsync/rename behavior. An accepted input which has not yet been formed remains durable; ordering and batch boundaries are explicit. The first unformed input or unknown batch blocks its session, but not another session. A failed save poisons the journal; there is no volatile fallback. The underlying journal still depends on private trusted local storage and a cooperative lock; it has no rollback protection or distributed fencing. Operator lock recovery, authenticated reconciliation, capacities, resource exhaustion, provenance reconstruction, explicit results from every production exit and further crash-injection testing remain unresolved. Do not enable production integration.
