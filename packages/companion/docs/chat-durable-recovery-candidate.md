# 加密聊天日志恢复：隔离候选，尚未上线

本候选没有接入 `brain.js`、`index.js` 或生产配置，也没有生产密钥注入、审计或可信人工核验。不要把候选视为可直接投产。现有进程内恢复入口与本候选不是同一个持久化实现。

## 语义和授权边界

日志在任何外部行为之前将首条标记为 `unknown` 并 fsync；崩溃后仍是 `unknown`，阻断同会话后续条目，不能自动重试。`startDurableChatRecovery(journal,{directory})` 复用仅限 Unix 域套接字的恢复协议；服务运行用户及 root 可操作，目录 0700、套接字 0600。拥有同一 UID 的任何进程都能调用，**不是人工在场认证**，也无法证明人工核验发生；应用、依赖、同 UID 进程或 root 受到控制时不安全。必须将服务 UID 与其他程序隔离，确保目录全部祖先不可被非可信用户写入，不得通过 HTTP 或聊天代理套接字；生产使用前须独立安全审计并定义可信操作者、身份认证、授权、隔离与审计机制。

`list` 仅返回随机能力 ID、进程内临时指纹及 UTC 尝试时间（旧数据可能为空），不返回账号、会话或正文；这里指纹按回合产生，不是跨回合稳定会话身份。时间仅表示开始处理，不是送达证据。指纹不能反推身份；如果无法从外部权威记录和足够上下文唯一匹配该回合，必须取消，不得猜测。只有独立核实并获授权后才能选择 `delivered` 或 `discard`，两者均永久跳过该未知回合，绝不重发；后一条是否处理由外部调用者决定。非预期 decision 被拒绝，已使用的能力失效。处理删除在确认前已同步到磁盘；确认或通信中断不代表失败，须重新查询，不得盲目重发。

持久日志不保存决策、核验依据或操作者，也无回滚/历史审计。上线必须先设计独立防篡改审计、最小化敏感信息、保留期限、误操作纠正方案和可靠身份绑定。相同 UID 可绕过此接口直接修改进程内对象或日志文件，可信边界必须覆盖整个服务进程。由于底层仅有协作锁，必须保证唯一写者，不能在日志运行时手工移除锁。

## 密钥管理策略（部分隔离候选，非生产方案）

- `initializeDurableChatKey(absolutePath, {directory})` 是显式离线初始化 API，要求提供绝对路径的私有日志目录，并持有日志协作锁、确认目录除锁外为空；已存在任何内容、遗留临时密钥或锁时拒绝创建。调用者必须确认所给目录确实是目标队列的唯一日志目录，且密钥未被其他目录的日志使用；代码无法发现其他路径中的历史数据。仅适用于所有其他写者已停止、可信本地文件系统和可信同 UID 的场景。密钥以 0600 临时文件同步后不覆盖发布；创建过程中任何失败会保留锁，可能保留目标密钥或临时硬链接，不可盲目重试。崩溃后应停掉所有写者，人工核对日志、密钥与同 inode 链接并从可靠备份恢复；不得重新生成替代已有日志的密钥。没有实现版本化密钥轮换或自动恢复，不应将此候选用于生产轮换。

- 每个部署使用加密安全随机生成的独立 32 字节 AES-256 密钥；禁止硬编码、提交到仓库、命令行参数、日志、消息或可共享环境变量。候选构造器只接受调用者提供的 Buffer，不管理密钥来源；运行时内存和副本不能保证完全擦除。
- 使用经批准的密钥管理器或系统凭据注入，按专用服务身份最小授权读取；加密日志和密钥分开存放及备份。上线前实际验证交付链、访问权限、轮换、撤销、加密备份及灾备恢复；丢钥则日志不可恢复。
- 当前格式没有密钥版本、在线轮换、可信反回滚或防旧备份重放机制。禁止简单替换密钥；须设计经测试、离线单写者、可回滚且可验证的重加密迁移及密钥版本管理，建立独立防回滚锚点。磁盘加密不能替代访问控制及密钥管理。
- 限制密文、临时文件、备份保留时间与权限；fsync 和原子 rename 的假设须在目标本地文件系统、实际挂载和断电场景验证，不假设网络文件系统等具有相同语义。

## 崩溃与处置

SIGKILL 会留下 `.journal.lock` 和可能的 socket 目录。先独立确认所有写者已停止、数据目录可信且没有正在启动的写者，再由授权运维检查并清除残留锁及套接字目录；不得跟随符号链接或递归删除不明文件。重启重新解密后应先核对 unknown，不能因重启自动重发。加密鉴别失败、锁异常、fsync 失败都必须停止处理并人工调查。已有隔离测试覆盖进程 SIGKILL 和确认后再启动，不等于掉电、磁盘损坏、备份回滚或所有崩溃窗口均已验证。
