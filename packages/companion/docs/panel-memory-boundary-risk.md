# LAN panel security boundary

The LAN panel remains unauthenticated by design. Its chat turns use a distinct `panel:` session and do not confer QQ owner privileges or use QQ conversation history in the Brain. The current chat snapshot reads only rows explicitly matching the configured `panel:` session from `panel-chat-tail.jsonl`, or, when that file is absent, from `turns.jsonl`. It does not read the legacy `chat-tail.jsonl` or fall back to QQ/Bilibili private turns. Older implementations did expose those records; existing legacy files may still contain shared private content and are neither migrated nor deleted. This boundary is not general access control: anyone who can reach the panel can use its available endpoints, and other panel endpoints and host/network controls have not been comprehensively audited here. Use only on the trusted LAN; do not expose the panel to an untrusted LAN or the Internet. Treat OneBot transport authentication and same-process code as trusted infrastructure; possession of an authentic event object is a capability, not proof against hostile code running inside the service.
