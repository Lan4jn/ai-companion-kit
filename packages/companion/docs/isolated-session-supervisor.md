# Linux isolated session primitive — disabled, not production ready

`scripts/isolated_session_supervisor.py` provides a programmatic root-owned, trusted-caller-only session primitive. It creates a fresh network namespace, drops to a specified non-root UID/GID with supplementary groups cleared and `no_new_privs`, gives the child one connected socket as FD 3, and closes the socket and kills the child process group on close, timeout, or leader exit. Its broker **always returns 403** and has no external listener: official domains are not reachable through it. It does not implement an authenticated management endpoint, a real request broker, browser setup, or either site's login. It is not wired to the panel or production configuration.

This is not a complete security boundary: untrusted commands can create new sessions or exploit shared UID/filesystem/IPC; process-group cleanup is not a substitute for a dedicated cgroup with `KillMode=control-group`. There is no mount, PID, IPC, filesystem, resource, or per-session UID isolation, authenticated management API, safe browser profile storage, owner-consent protocol, or authoritative identity verification. Never run a browser or real account with this primitive as-is. The caller must only supply trusted fixed argv, never HTTP/user-controlled commands. The environment is intentionally minimal.

Root and `CAP_SYS_ADMIN` (or equivalent namespace permissions), `/usr/bin/unshare`, `/usr/bin/setpriv`, and `/usr/bin/python3` are required. Run the isolated system tests with `python3 -m unittest test/isolated_session_supervisor_test.py -v`; they skip when namespace privileges are unavailable. No official website or account is contacted. Further integration requires cgroup and filesystem/IPC isolation, dedicated session identities, an independently reviewed FD broker and policy, authenticated management with lifecycle binding, and explicit user-operated login/verification. Until those prerequisites are met do not enable official domains or claim real-login readiness.
