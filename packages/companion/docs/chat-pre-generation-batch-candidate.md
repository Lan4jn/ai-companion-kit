# Pre-generation durable batch candidate

`createPreGenerationBatchCandidate` is an isolated, default-disabled API. It is not wired into production ingress, recovery or `handleTurn`. The older `createTrustedBatchGenerationCandidate` remains post-generation and does not provide this guarantee. Use a dedicated `EncryptedChatJournal`, an independently authenticated OneBot endpoint, an external 32-byte sealing key and a trusted local generator. The selected authenticated message snapshots, input IDs and destination are atomically replaced with a stable random batch ID and `generation-unknown` row, independently HMAC-bound before generator invocation. The generator receives frozen snapshots and `{batchId,batch,destination}`; `batch` is the JSON array of reconstructed normalized messages, not a live `handleTurn` item array. A one-use internal capability binds completion to the exact persisted reservation; successful output becomes a signed delivery batch with the same ID. Missing, modified, malformed, concurrent or unconfirmed generation remains blocked; restart never re-enters generation or tools through this candidate. No automatic reconciliation is implemented.

The second argument can be deliberately passed by trusted composition to an isolated tool-effect journal, but no production integration is asserted. Existing Brain/handleTurn tool-effect paths accept caller-supplied identities and are NOT authenticated by this candidate; raw journal/queue APIs and the old generator must not be exposed to untrusted code or mixed as a recovery entry point. The seal key, journal integrity and anti-rollback storage, process, transport authentication, generator, bot, and all privileged composition are trusted. Anyone holding the seal key or able to replace the journal/code can forge or roll back state; the HMAC does not prevent deletion or rollback. A hostile same-process caller can bypass API boundaries or invoke the generator/tools directly. Memory-only capabilities do not survive restarts; unknown outcomes require offline human reconciliation, not blind retries. Independent journals are not a distributed transaction; crashes may leave either effect or generation unknown. Tool code must itself journal every relevant external side effect; generation may have other untracked effects. Input message content is encrypted at rest by the journal but is handed in full to the trusted generator and should not be logged. The design is experimental, not a claim of exactly-once execution or production readiness.
